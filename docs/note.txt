5.finish responsive design and the complete WCAG audit.
This requirement means making the entire platform usable across different screen sizes and formally checking it against WCAG 2.1 Level AA.

Responsive design includes:

- Mobile, tablet, laptop, and large-screen layouts.
- No hidden controls, overlapping panels, or cut-off text.
- Reflow at 320 CSS pixels without unnecessary horizontal scrolling.
- Support for 200% browser zoom and increased text spacing.
- Responsive dashboards, tables, forms, dialogs, voice controls, and navigation.
- Readable touch controls while preserving keyboard interaction.

The complete WCAG audit covers all roles and pages:

- Candidate, employer, verifier, and administrator dashboards.
- Registration, login, profile building, applications, verification, privacy controls, and error states.
- Keyboard navigation, visible focus, correct focus order, and no keyboard traps.
- Screen-reader semantics, landmarks, headings, labels, instructions, and status announcements.
- Alternative text for meaningful images.
- Colour contrast: normally 4.5:1 for text and 3:1 for large text.
- Forms with understandable validation and accessible error messages.
- Accessible dialogs, file uploads, tables, tabs, and dynamic AI results.
- Page language, consistent navigation, skip links, and semantic HTML.
- Reduced-motion and orientation compatibility where applicable.

“Complete audit” should combine automated and manual testing. Automated tools alone cannot prove WCAG compliance. We should use browser accessibility tools alongside keyboard-only testing, screen-reader testing such as NVDA, zoom/reflow testing, contrast checks, and manual testing of every important workflow.

Definition of done:

- Every primary workflow works with mouse, keyboard, and screen reader.
- Mobile and 200% zoom layouts remain usable.
- No unresolved WCAG 2.1 Level A or AA violations.
- Automated scans have no serious accessibility errors.
- Issues and corrections are recorded in an audit report.
- Every corrected issue is manually retested.

The keyboard work already completed is one part of this requirement, but responsive layouts, screen-reader behavior, contrast, form validation, dialogs, and formal evidence still need a full review.

We’ll handle it in controlled phases so responsive fixes do not break the existing keyboard, voice, scoring, or account workflows.
